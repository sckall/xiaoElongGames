# 📰 NEWS-SYSTEM · 新闻系统规划

> **状态**：规划中（v0.3 起立项） · **阶段归属**：阶段 1（联机强化 + 海外社区）
> **维护者**：本文件随 git 分发，作为新闻系统的设计与决策记录。

## 背景

大厅顶部导航栏右上角长期挂着「铃铛」，但 v0.3 之前仅做 `window.alert("暂无新消息")` 占位，承载能力为零。

玩家打开游戏后需要一个统一的"信息流"入口：
- **系统/运营通知**：版本更新、维护公告、活动预告
- **数据看板**：婚姻登记、AI 模型价格、玩家社区指标等第三方公开数据
- **玩家动态**（远期）：好友上线、社群消息、战绩分享

把"通知 + 数据看板 + 玩家动态"三块统一为**新闻系统**，由同一组件承载。

## 目标

1. **统一入口**：大厅 / 活动中心 / 后续新页面的铃铛全部接入同一个新闻组件
2. **可承载运营推送**：支持运营人员发布公告，玩家进游戏即看到
3. **数据驱动**：第三方公开数据（可由后端代理抓取）能动态刷新，不写死在前端
4. **轻量解耦**：新闻系统不与具体业务页面耦合，可独立迭代

## 计划

### v2 · 接入后端 API（**下一步**）

**目标**：把写死数据迁出前端，改为运行时从 `apps/server` 拉取，"同步"按钮触发真刷新。

**API 设计**（待实现，提议）：

```
GET  /api/news/announcements?since=<timestamp>  → 公告列表（按发布时间倒序）
GET  /api/news/board/marriage                  → 婚姻数据最新 1 行
GET  /api/news/board/models?sort=cacheHit&limit=5 → AI 模型 Top N
POST /api/news/announcements/read              → 标记已读（body: { ids: string[] }）
```

**数据来源**：
- **婚姻数据**：民政部季度民政统计（公开网页，需爬或手动导入；无现成 API）
- **AI 模型价格**：Artificial Analysis（美元价）+ DeepSeek 官网国内价，需爬或手动维护
- **公告**：手动从 server 端文件 `apps/server/src/news/announcements.json` 维护

**降级策略**：
- 后端不可达 → 回退到前端 mock（保持 v0.3 行为）
- 抓取失败 → 返回最近一次成功缓存 + `stale: true` 标记，UI 标灰

**更新机制**：
- 客户端按需拉取（点开 bell 才请求）
- 后端定时任务每日凌晨 2:00 拉取一次第三方数据，写入 `apps/server/src/news/cache/`
- 紧急公告可手动写入 `announcements.json`，无需重启（hot reload or 重启一次）

## 设计决策

- **不复用玩家的 GameStateContext**：新闻系统是公共数据，不与玩家登录态绑定
- **不需要鉴权**：v2 所有 GET 接口公开；标记已读才需要带 playerId
- **不缓存到 localStorage**：公告有"过期"语义，每次开 bell 走网络拿最新；模型/婚姻数据可短缓存（5 分钟）
- **不用 Service Worker 推送**：阶段 1 暂不接 Web Push，依赖玩家主动开 bell

## 不做什么（避免范围蔓延）

- ❌ 评论区 / 点赞 / 关注（社交化，v4+）
- ❌ 个性化推荐算法（v4+）
- ❌ 推送通知（Web Push / 移动 Push，v4+）
- ❌ 复杂的 CMS 后台（先靠 JSON 文件 + Git 维护）
- ❌ 实时聊天（这是另一个独立模块）
